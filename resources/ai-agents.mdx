The Andi AI Search API is built for AI agents. You can call the REST endpoints from agents you build (see the [quickstart](/getting-started/quickstart) and [AI agent tool example](/examples/ai-agent-tool)), or connect the MCP server to your coding tools for web search and page fetch.

## Andi Search MCP server

Use Andi as your agent's web search and page fetch tool over the [Model Context Protocol](https://modelcontextprotocol.io/).

**Server URL:** `https://api.andiai.com/mcp`

**Transport:** Streamable HTTP

**Authentication:** Pass your API key in the `x-api-key` header. Get a key from the [API Console](https://console.andiai.com/signup).

Your API key is account-level, not project-level, so a system-wide install works everywhere at once. Each client below notes how to choose between project and system-wide scope.

### Claude Code

For the current project:

```bash
claude mcp add --transport http andi https://api.andiai.com/mcp --header "x-api-key: YOUR_API_KEY"
```

System-wide, for all projects:

```bash
claude mcp add --scope user --transport http andi https://api.andiai.com/mcp --header "x-api-key: YOUR_API_KEY"
```

### Cursor

Add to `.cursor/mcp.json` in your project, or to `~/.cursor/mcp.json` for all projects:

```json
{
  "mcpServers": {
    "andi": {
      "url": "https://api.andiai.com/mcp",
      "headers": {
        "x-api-key": "YOUR_API_KEY"
      }
    }
  }
}
```

### Claude web and desktop

Add this as a custom connector in your MCP server settings:

```json
{
  "mcpServers": {
    "andi": {
      "url": "https://api.andiai.com/mcp",
      "headers": {
        "x-api-key": "YOUR_API_KEY"
      }
    }
  }
}
```

### VS Code

Add to your VS Code settings (JSON):

```json
{
  "mcp": {
    "servers": {
      "andi": {
        "type": "http",
        "url": "https://api.andiai.com/mcp",
        "headers": {
          "x-api-key": "YOUR_API_KEY"
        }
      }
    }
  }
}
```

### Codex CLI

Add to `~/.codex/config.toml` (system-wide — Codex config applies to all projects), with `ANDI_API_KEY` exported in your shell:

```toml
[mcp_servers.andi]
url = "https://api.andiai.com/mcp"
env_http_headers = { "x-api-key" = "ANDI_API_KEY" }
```

The same config is shared by the Codex CLI, IDE extension, and ChatGPT desktop app.

### Other MCP clients

Any client that supports the Streamable HTTP transport can connect: server URL `https://api.andiai.com/mcp`, with your API key in the `x-api-key` request header.

### Stdio-only clients

For MCP clients that only support the stdio transport, the [Andi CLI](/getting-started/cli) runs a local server exposing the same tools:

```json
{
  "mcpServers": {
    "andi": {
      "command": "npx",
      "args": ["-y", "@andiai/cli", "mcp"],
      "env": { "ANDI_API_KEY": "YOUR_API_KEY" }
    }
  }
}
```

## MCP tools

### `andi_web_search`

Searches the web and returns LLM-ready markdown. Wraps `GET /api/v1/search` with `format=context` and `metadata=agent`.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `q` | string | — | Search query. Supports [query operators](/features/query-operators). Required unless `queries` is supplied. |
| `queries` | array of strings | — | Run up to 5 related queries in one call and get fused, deduplicated results. Alternative to `q` — supply exactly one of the two. |
| `limit` | integer | `10` | Results to return (1–50) |
| `offset` | integer | `0` | Skip this many results — paginate deeper into an existing result set without re-searching |
| `searchMode` | string | `auto` | `auto` (default) sets the search effort per query automatically. Fixed modes — `low-cost`, `fast`, `balanced`, `deep`, `exhaustive` — pin an effort level: `fast` ~1s lowest latency; `balanced` ~1–2s everyday web search; `deep` ~2–3s adds spell correction and broader coverage; `exhaustive` multi-round agentic retrieval (up to ~15s). |
| `effort` | string | — | Pins an effort level by generic tier name instead of a mode: `low`, `medium`, `high`, `max`. An explicit `searchMode` wins over `effort`. Omit for adaptive. |
| `content` | boolean | `false` | Include cleaned page content for each result. Increases cost and tokens. |
| `maxContentLength` | integer | — | Maximum content characters per result when `content=true` |
| `country` | string | — | ISO 3166-1 country code (e.g., `US`, `GB`) |
| `language` | string | — | ISO 639-1 language code (e.g., `en`, `es`) |
| `safe` | string | — | Safe search: `off`, `moderate`, or `strict` |
| `dateRange` | string | — | Recency filter: `24h`, `7d`, `30d`, `90d`, `1y` |
| `includeDomains` | string | — | Comma-separated domains to restrict results to |
| `excludeDomains` | string | — | Comma-separated domains to exclude |
| `types` | string | every array except `images` | Comma-separated list of which result arrays to return: `web`, `news`, `videos`, `images`, `social`, `academic`, `places`, `profiles`, `tools`, `docs`, `agents`, `all`. See [response type selection](/features/query-parameters#response-type-selection). |

<Note>
The MCP tool caps `limit` at 50. The REST endpoint allows up to 100.
</Note>

MCP requests are agent requests by definition, so results carry the agent-first fields described below — `agent`, `quickstart`, the compact `reader` object, and `tools`/`docs`/`agents` arrays — plus a per-call `cost_dollars`. Results default to extracts; set `content=true` or follow up with `andi_fetch_url` only when extracts aren't enough.

### `andi_fetch_url`

Fetches a web page and returns its content as LLM-ready markdown. Wraps `GET /api/v1/fetch`.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `url` | string | **required** | URL to fetch |
| `query` | string | — | What you want from the page. Returns query-focused extracts (`query_extracts`/`query_snippet`) instead of only full content. |
| `maxContentLength` | integer | `100000` | Maximum content length in characters (minimum 500, maximum 200000) |

See [content retrieval](/search/content-retrieval) for the full fetch endpoint reference.

### Error handling

MCP tool errors come back as a text result with `isError: true`, not a raw HTTP status — the message is written for the calling agent to act on:

| Cause | What the agent sees |
|---|---|
| Rate limited (`429`) | Retry-after guidance in seconds |
| Out of credits (`402`) | A message pointing to [console.andiai.com](https://console.andiai.com) to top up |
| Temporarily unavailable / still warming (`503`) | A retry hint, with a wait time when the server provides one |
| Fetch page-level failure (`422`) | The reason (`not_found`, `blocked`, or `unextractable`) and a note that retrying the same URL won't help |

## Agent Skill

The API hosts an installable [Agent Skill](https://agentskills.io/) that gives agents a description of the search tool, its parameters, and usage guidance. Agents that support skills can install it directly:

```bash
npx skills add https://api.andiai.com/.well-known/skills/andi-web-search/SKILL.md
```

The skill is also available at `https://api.andiai.com/.well-known/agent-skills/andi-web-search/SKILL.md`, with an index at [`/.well-known/agent-skills/index.json`](https://api.andiai.com/.well-known/agent-skills/index.json).

### Claude Code plugin

The [`andisearch/andi-agent-skills`](https://github.com/andisearch/andi-agent-skills) repository doubles as a Claude Code plugin marketplace. The `andi` plugin installs the `andi-web-search` skill and connects the hosted MCP server in one step:

```text
/plugin marketplace add andisearch/andi-agent-skills
/plugin install andi@andi-agent-skills
```

Set `ANDI_API_KEY` in your environment before first use.

### Install from the GitHub repo

The same repository works with the skills CLI — `npx skills add andisearch/andi-agent-skills` — and with Codex's skill installer. See the [repo README](https://github.com/andisearch/andi-agent-skills#install) for the full install matrix, including the Codex plugin.

## Agent-first responses

The API supports `format=context`, which returns search results as markdown with YAML frontmatter — sized for LLM context windows and ready to use without JSON parsing. See [response format](/features/response-format) for the full contract.

Beyond the format, results can carry agent-specific fields — which `.md` version of a page exists, its site's llms.txt index, an MCP server URL, an install command — so you can act on a result without a follow-up fetch.

### What counts as an agent request

A request is an agent request when it matches **any one** of the following. You don't need all of them:

- `metadata=agent`
- A request through the MCP server or the [CLI](/getting-started/cli)
- `format=context`
- `Accept: text/markdown`
- `intent=AgentToolsIntent`
- A `types` value naming `tools`, `docs`, or `agents`

`metadata` defaults to `agent` automatically when any of these signals is present and you didn't set `metadata` yourself. A plain JSON request's response shape is unchanged unless you opt in.

### What changes

- Each result may carry a compact `agent` object: which `.md` version of that page exists, the llms.txt index covering its path (with links filtered to your query), the site's permissions for AI use, and the origin it belongs to — plus a `quickstart` summary (MCP URL, install command, docs link) computed with no extra fetch.
- Top-level `extracts` (query-relevant passages) defaults to on for agent requests.
- Three extra arrays group agent-relevant results the same way `news`/`videos` do: `tools`, `docs`, `agents`. `agents` holds one entry per site in the results that publishes anything for agents — the ranked result itself, in the ordinary result shape, plus that site's full catalog: llms.txt tree, MCP server card, OpenAPI/API catalog, skills, install and auth guides, permissions, and sitemaps. An origin appears here only because a page from it is already in `results`; origins are never added on their own. `agents[]` is capped at `limit`, the same as the other arrays.
- `metadata=agent` also keeps a compact `reader` object per result — word count, access class, authors, keywords, alternate formats (including the `.md` twin) — plus, when the page's own structured data has them: FAQs, listing items with ratings, how-to steps, breadcrumbs, `sameAs` links, and named entities. Never page bodies unless you also pass `content=true`.
- With `extracts=true` (the default for agent requests), each site's own agent files — llms.txt, install.md, skills, and similar — come back with query-relevant passages of their own; with `content=true`, their full markdown. Both ride inside that site's entry in `agents[]`. Ask for neither and those files still appear, just without their own text.
- By default, an agent request's arrays other than `results` and `images` have the items already present in `results` removed, so you don't pay context budget for duplicates. Set `types=all` to get everything, undeduplicated.

### The result.agent object

```json
{
  "origin": "https://docs.slack.dev",
  "page": {
    "markdown_url": "https://docs.slack.dev/ai/slack-mcp-server.md",
    "llms_txt": { "url": "https://docs.slack.dev/llms.txt", "scope": "root" },
    "links": [{ "title": "MCP server setup", "url": "https://docs.slack.dev/ai/slack-mcp-server" }]
  },
  "permissions": { "search": "allow", "ai_input": "allow", "ai_train": "disallow" }
}
```

`origin` is the key into the response's `agents[]` array — look up the matching item there for the site's full catalog. `permissions` only appears when the page's own permissions differ from the site's. `result.quickstart` sits alongside `agent` at the top level of the result, never nested inside it.

### The agents array

Each item is a full result — the same shape as an item in `results` — plus the site's full `agent` catalog:

```json
{
  "title": "Slack API docs",
  "link": "https://docs.slack.dev",
  "desc": "Build apps for Slack.",
  "source": "docs.slack.dev",
  "agent": {
    "origin": "https://docs.slack.dev",
    "capabilities": { "accepts_markdown": true, "webmcp": false },
    "surfaces": [
      { "kind": "llms.txt", "url": "https://docs.slack.dev/llms.txt", "scope": "root", "link_count": 42 },
      { "kind": "mcp-server-card", "url": "https://docs.slack.dev/.well-known/mcp/server-card.json" },
      { "kind": "install-md", "url": "https://docs.slack.dev/install.md" }
    ],
    "permissions": { "search": "allow", "ai_input": "allow", "ai_train": "disallow" },
    "sitemaps": ["https://docs.slack.dev/sitemap.xml"]
  },
  "quickstart": {
    "mcp": { "url": "https://docs.slack.dev/mcp", "transport": "http" },
    "llms_txt": { "url": "https://docs.slack.dev/llms.txt", "scope": "root" }
  }
}
```

Because `agents[]` items carry the full result shape, you get the content you need — `reader`, `extracts`, `snippet`, and `content` when requested — straight from the array, at the depth your request asked for.

### Context format blocks

At `metadata=agent`, `format=context` articles carry the same full frontmatter as `metadata=full` — `domain`, `publisher`, `type`, `content_type`, `lang`, `word_count`, `image`, `keywords`, `summary` when available — in addition to the agent blocks below.

An `<agent_index>` block appears once, near the top of the response, with one line per site in `agents[]`:

```text
<agent_index count="1">
- docs.slack.dev: mcp https://docs.slack.dev/mcp; docs https://docs.slack.dev/llms.txt (42 links)
</agent_index>
```

When you pass `extracts=true` or `content=true`, that site's own content-bearing agent files (llms.txt, install.md, skills) render inside `<agent_index>` as `<surface>` blocks — query extracts, full markdown, or both:

```text
<agent_index count="1">
- docs.slack.dev: mcp https://docs.slack.dev/mcp; docs https://docs.slack.dev/llms.txt (42 links)
<surface origin="docs.slack.dev" url="https://docs.slack.dev/llms.txt" kind="llms.txt">
<extracts>
> The Slack MCP server exposes channel and message tools over the Model Context Protocol.
</extracts>
</surface>
</agent_index>
```

A per-result `<agent>` block appears after `<extracts>` inside each `<article>`, with that page's own agent facts:

```text
<agent origin="https://docs.slack.dev">
use:
  mcp: https://docs.slack.dev/mcp (http)
docs:
  index: https://docs.slack.dev/llms.txt (scope: root)
  page_md: https://docs.slack.dev/ai/slack-mcp-server.md
  links: 3 matched "slack mcp server"
permissions: ai_train=disallow
origin: see agent_index docs.slack.dev
</agent>
```

When the page's own structured data has FAQ, listing, or breadcrumb content, `<faq>`, `<items>`, and `<breadcrumbs>` blocks render inside the `<article>` after `<extracts>`, using the same data as `reader.faqs`/`reader.items`/`reader.breadcrumbs`.

## llms.txt

The site publishes [llms.txt](https://llmstxt.org/) files that list all documentation pages with direct markdown URLs.

| File | Contents |
|---|---|
| [`/llms.txt`](https://docs.andiai.com/llms.txt) | Page titles and descriptions with markdown links |
| [`/llms-full.txt`](https://docs.andiai.com/llms-full.txt) | Full page content inlined as markdown |

Use `/llms.txt` for discovery and navigation. Use `/llms-full.txt` when you need the complete documentation in a single request.

## Markdown content negotiation

Any docs page returns clean markdown when requested with the `Accept: text/markdown` header. The markdown response includes YAML frontmatter.

```bash
curl -H "Accept: text/markdown" https://docs.andiai.com/getting-started/quickstart
```

The response includes `Link` headers pointing to `/llms.txt` and `/llms-full.txt`, and an `X-Llms-Txt` header.

## AI crawler access

The site's `robots.txt` explicitly allows AI crawlers including GPTBot, ClaudeBot, and PerplexityBot.
